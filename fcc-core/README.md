# FCC Control Studio 1.5 — 通用控制基座 + 需求采集 + 长期反馈

这是 FCC Core 原有功能上的增量修订，**保留经典/高级控制数学 SDK、执行引擎、专家面板**；新增**通用目标采集与量化模型层 Commissioning**、长期节点报告和人工干预验证记录。适用于建立任何**能够转化为可观测指标**的持续优化任务，而非预置某一个行业应用。

## 30 秒理解架构

- **I 输入层（首次向导）**：用户的最终结果、量化指标、目标关系、来源与采样节拍、控制权限、报告节拍和风险约束。
- **Quantification 量化层**：校验缺项、数据可观测性、评价频率、是否有可控手段；将已确认信息编译成 FCC LoopConfig。它**不凭自然语言猜测动态系统数学矩阵或能自动做的控制动作**。
- **FCC Core 控制基座**：现有 PID/MPC/Kalman/ARX 等高级数学能力以及单机持久化调度、采样、偏差评估、权限控制、审计、动作与验证机制。
- **O 输出 + Checkpoint**：区分已接收数据、AI 推断、待验证状态；定时生成 SQLite 报告收件箱、历史趋势、待确认干预、下一步建议。
- **Strategy Learning（受监督）**：登记候选措施 → 真实执行确认 → 等待响应 → 新的观测 → 前后评估。未实现自动持续尝试各种动作，也不宣称仅凭前后比较可以证明因果。

## 运行

需 Python 3.11+。首次安装依赖需要网络。

```bash
cd fcc-core
python -m pip install -e '.[test]'
python -m fcc.server --host 127.0.0.1 --port 8099 --db fcc.db
```

- **首次使用 / AI 能力识别（推荐）**：http://127.0.0.1:8099/start
- **建立长期项目**：http://127.0.0.1:8099/setup
- **原 I/O 计算工作台**：http://127.0.0.1:8099/easy
- **专家工程面板**：http://127.0.0.1:8099/expert
- **API 参考**：http://127.0.0.1:8099/docs

也可以使用本目录 `启动FCC-Windows.bat` 或 `bash 启动FCC-Mac-Linux.sh`。**关闭窗口服务就会停止调度与报告生成**，需要持续运行的服务主机或受监管的守护进程。数据仍保存在 SQLite 中。

## AI 入口和受控部署

从仓库根目录运行 `python fcc-skill/scripts/fcc_bootstrap.py doctor --json` 进行只读检测。只有得到明确授权，才执行 `install --yes` 与 `serve --yes`。聊天 AI 没有本机代码权限时只能使用 SKILL 完成手动访谈与复盘。详情在根目录 `首次使用-给AI的说明.md`。

## 首次向导如何使用

1. **结果**：用自然语言说最终要改进什么，不必先提 PID/MPC。
2. **量化**：给出主指标、单位、`至少达到` / `不高于` / `接近数值`、目标值和容差。目标和代理指标要区分。
3. **输入**：申明数据来源（实测、人工、AI 推断）、采样节拍、如何把数据送入 FCC。手动数据不会自动产生；AI 推断须附置信度与证据且不能独立证明成功。
4. **节奏**：独立选择评价频率和报告频率，必要时配置执行后的验证等待时间。报告目前仅在**本地收件箱**，不是聊天提醒。
5. **边界**：填写可调整的手段、禁止的行为、潜在副作用，选择仅观察/建议/人批准。
6. 点击 **完成并量化建模**，核查 FCC 输出的有效配置；点击 **确认并启动监控** 后，定时评价才开始。
7. 持续用人工或外部数据适配器提供观测；到节点读取报告、选择是否实施建议、登记实际执行证据、新数据再验证。3 次连续达标的默认要求必须满足采样间隔，不允许 3 次瞬间重复报告假装长期稳定。

## 真实边界

- 初次向导默认只生成 **监控回路 + 观察建议**；即便用户填写动作名称，也没有对应的已授权 API/设备执行器，**不自动采取动作**。
- 原核心单回路执行链为 SISO，1.5 向导以**单一主数值指标**为完整测试范围。多指标矛盾、非数值测量、真实非数值执行及完整 MIMO 行为仍需扩展适配器与多目标约束。
- 内建 Kalman/MPC/PID 等是**具备模型时可用的算法库**，不是任何通用目标的自动正确解。
- 阶段报告可持久化并被其他 AI 通过 API 拉取；**没有实现聊天/邮件主动推送、系统守护部署、云端身份认证和高可用调度**。
- 没有足够新鲜且非 AI 推断的观测，不会声称稳定达标。人工数据来源声明并不等于第三方核验；用于重要决策前仍需要独立校验。
- HTTP 接口 **无身份认证**，只适合本机或可信隔离开发环境，绝对不可直接暴露公网或连接高风险物理设备。
- 真实控制需要另外接入设备适配器、读取已施加输入、定义硬约束、仿真、人工审查及硬件安全措施。
